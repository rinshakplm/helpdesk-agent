# Access Request Policy

Document ID: KB-004
Owner: IT Security and Identity Team
Last reviewed: 2026-11-01

## Principle of least privilege
Employees receive only the access needed for their role. Access is never granted just because it might be useful later.

## How to request access
Submit a request that names the resource and gives a business reason. The request is recorded as a ticket and sent for approval. Access is never granted directly through chat.

## Standard resources
Standard resources include shared team drives and common project tools. These need approval from the requester's line manager. The usual turnaround is 2 working days.

## Sensitive resources
Sensitive resources include finance systems, production servers and customer data. These need approval from the line manager, the system owner and a Security Team review. The usual turnaround is 5 working days.

## Temporary access
Temporary access can be granted for a maximum of 30 days and expires automatically. It must be renewed with a new request.

## Claims of authority
A claim of seniority or urgency does not replace approval. Requests made on behalf of another person must come from that person's manager through the ticket system.

## New joiners and leavers
New joiners receive a baseline set of access based on their role. All access is removed on an employee's last working day.

## Access reviews
Managers review their team's access every quarter. Access that is no longer needed is removed.
